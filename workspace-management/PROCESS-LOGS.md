# 子プロセス出力の保持と一時ログ容量

作業ブランチの `bounded_process.py` は、一時ファイルへの書き出しをパイプ回収へ変更しました。各ストリームの先頭を既定2MiBまで保持し、出力超過・中断・時間切れでも部分ログと後始末の結果を残します。固定キット20261019.4は従来の一時ファイル方式のまま保持しています。

## 変更の理由と方式

従来は保持するログの量だけに上限があり、監視の間隔や中断猶予の間は一時ファイルが増加しました。新方式は収集用の一時ログファイルを作らず、OSの容量が有限なパイプから読み取ります。上限超過時は従来どおり終了コード125です。中断猶予がある場合は監督プロセスへ通知し、猶予中も出力を読み捨てるため、後始末の処理が満杯のパイプで停止することを避けます。

| 比較 | 判断 |
|---|---|
| 一時ファイルの定期切詰め | 書込み側の位置と競合し、疎ファイル化や上限超過を防ぎ切れないため不採用 |
| POSIXのファイルサイズ制限 | Windowsと同じ動作にできず、子自身の保存処理にも影響するため不採用 |
| 読込みスレッド | 管轄外の子孫がパイプを保持した際の停止・ハンドル回収が複雑になるため不採用 |
| スレッドを使わないパイプ回収 | POSIXは非ブロッキング読込み、Windows/Python3.11以降はPeekNamedPipeで利用可能量を確認して読込む方式を実装 |

両ストリームに1巡あたり各256KiBの回収枠を割り当て、期限の確認やもう片方の出力が無期限に待たされないようにします。後始末後の回収も16巡までとし、読み残しが続いた場合は125/CaptureDrainLimitExceededにします。パイプ読込み失敗も成功扱いにはしません。

## 結果に追加する情報

| フィールド | 意味 |
|---|---|
| capture_transport | 新方式ではbounded-pipes |
| disk_spool_bytes | 収集用の一時ログへの書込みは0。実行対象自身によるファイル書込みは含まない |
| output_byte_counts | observed。stdout_bytes/stderr_bytesは実際に回収したバイト数で、子が書こうとした全量ではない |
| output_pipe_eof | stdout/stderrそれぞれでEOFを観測できたか。管轄外のプロセスが保持するとfalseになり得る |
| truncated | どちらかの回収量が保持上限を超えた場合にtrue |

ログは各ストリームの先頭を保持し、従来どおりstdoutの後にstderrを連結します。両者の時間順序までは復元しません。UTF-8でないバイトはエスケープして表示するため、表示文字数・JSONのサイズは保持バイト数と同じではありません。

## 検証と配布範囲

大量出力・両ストリーム同時出力・上限ちょうどの出力・後始末中の大量出力・終了後の子孫出力・非UTF-8・中断・時間切れ・Job割当失敗を検証します。POSIXでは管轄外セッションがパイプを保持していても、制御側がEOF待ちで停止せず、読込みスレッドを残さないことも確認します。

OSのパイプ容量や対象プロセス自身のメモリ・保存ファイルをこのツールで制限するものではありません。切り離されたPOSIXセッション、外部デーモン、制御側のSIGKILLは引き続き停止の保証範囲外です。Windows Job / POSIXプロセス群の所有範囲は従来どおりです。

この変更は作業ブランチのソースのみです。新方式のネイティブCI確認後に、別バージョンの配布候補へ組み込む予定です。固定ZIPと過去の検証記録を上書きしません。
