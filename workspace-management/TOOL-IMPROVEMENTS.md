# リポジトリ・ツール・制作物の統合と改良

更新：2026-10-14（日本時間）。[成果物17件](artifacts.md)、管理17機能、製品10件の一覧は役割を分けています。製品本体は9件未取得で、管理テストの合格を製品完成に転用しません。

## 今回の実装

| 対象 | 改良 | 検証・結果 |
|---|---|---|
| 実行入口と入力登録 | 候補レポート生成・取得済み監査コードの検証入口、2件の登録漏れを修正 | 先頭引数に直接指定したスクリプトは直接／共通入力への登録を必須化。作業ディレクトリからの相対参照も検査 |
| 設定の重複 | 入力・依存・コマンドの二重定義と、標準検査の同一呼出しを検出 | 同一cwd・argvの時間制限が食い違う場合はエラー。意図的な別ツールからの共用は通知 |
| 失敗した設定検査 | 検査前に未完了状態を保存し、失敗を記録 | 以前の合格を新しい確認として表示しない。破損時は独立したcheck_settings.pyで診断 |
| 配布設定 | 処理が参照しないlayoutをlink_modeへ修正 | 新版はlink_mode=direct。生成後のカタログ内にシンボリックリンクがないことを検査 |
| 配布・導入 | 更新24ファイルと基準ZIP・検証ヘルパーを新しいキットに統合 | 固定公開版から二重ビルド一致、全ハッシュ、実CLI適用後の6環境CI合格 |
| 旧版の保存 | 17／20ファイル版と旧キットを固定履歴として保持 | 旧版の内容を変更せず、旧ヘルパーは作成時のSHA256で照合。新版へ追加した検証とは分ける |

配布設定のlayout誤用は前回のCIでは見落としていました。新版は正しい項目を使い、CIにもリンク状態の追加検査を入れました。旧版の合格を「生成後にもリンク不要」の確認へ読み替えません。

## 設定の役割と使い方

| 正本 | 管理するもの | 確認方法 |
|---|---|---|
| registry.json | 実行入口・入力・依存・時間制限・共通入力グループ | `python tools/check_settings.py` または共通runのsettings-consistency |
| catalog/config.json | 一覧の取得元・対象範囲・link_mode | build/check。layoutは新版で拒否 |
| Python依存ロック | 版・配布SHA256・ビルド依存 | 新規仮想環境のsetup、python-environment |
| catalog/artifacts.json | 制作物の版・本文SHA256・公開状態・検証範囲 | 成果物一覧、公開本文照合、更新候補の比較 |

設定検査は直接スクリプトと明示登録した入力、同じ作業ディレクトリ・引数の整合性が対象です。モジュール解決・テストディレクトリ内の全コード・全間接依存を推論する検査ではありません。
