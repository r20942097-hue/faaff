## 導入結果の見方

ZIPを新しいフォルダへ展開し、新規仮想環境のPythonで `tools/manage.py setup` を実行します。結果は `catalog/results/python-setup.json` に保存します。`status` が全体の結果、`checks` が実行順の記録です。各行の `argv` で対象、`output` で原因、`exit_code` で終了理由を確認します。

| 表示・終了コード | 意味 |
|---|---|
| running / exit_codeがnull | 起動前・実行中・終了未確認。合格として扱わない |
| passed / 0 | 処理が完了して合格 |
| failed / 124 | 時間切れ。保存した標準出力・標準エラーの部分ログを確認 |
| failed / 127 | 起動失敗。実際の例外型とメッセージを確認 |
| interrupted / 130 | ユーザー中断。実行済み結果を保持し、残りを停止 |
| failed / その他 | 対象コマンドが返した終了コードと出力を確認 |

全子孫プロセスの停止や、中断した処理の部分出力保存まで保証するものではありません。元の管理・監査73ファイルは保持し、共通処理はアダプター・管理側に実装しています。今回の一覧UI実装は変えておらず、35項目は既存の画面検証記録です。

## 公開記録の共通確認と更新案

開発側の共通登録を16機能へ拡張し、artifact-publicationを追加しました。固定公開版のサイズ・SHA256、現在の固定main本文、PRの状態とマージ先を確認し、結果を保存します。実際に12成果物を確認し、7件がmainの本文と一致、5件はPR側の固定公開版と一致しました。main以外へのPRマージだけではmain反映に昇格しません。

正本は自動変更せず、必要なら新規work JSONへ更新案を書きます。ネットワーク障害・未完了の確認・別の正本への古い確認結果から更新案を作りません。CIの確認日を本文の再取得日で上書きしません。14回帰でこれらの境界を検証しました。公開ZIP20261012.2は従来の15機能を含む固定版で、新しい16機能の候補コードとは別です。

解凍・候補適用後の共通入口は `python tools/manage.py run --tool artifact-publication`、更新案だけを出す入口は `python tools/check_artifact_publication.py --candidate work/artifacts-proposal.json` です。

共有ルールの関係は原本SHA256と、順序を保ったルール・制御行の比較に基づきます。確認できる手元の原本があれば再照合します。制御行や順序を変えた本文を同一と扱わず、ファイルの自動削除や製品動作の同一性を保証する用途には使いません。
