# 成果物一覧の見方・更新方法

[成果物一覧](artifacts.html)では、配布ZIPと広告・追跡・日本語表示等の13成果物を探せます。全ファイル・管理機能・10製品の一覧は別の目的の表です。録画等の未取得本体を完成品として数えません。

## 見方

1. 名前・用途・版で検索し、公開状況と種類で絞り込みます。登録順・名前順・確認日が新しい順・サイズが小さい順で並べ替えられます。同じ値は登録順を保ち、「条件を解除」で登録順へ戻ります。確認日は公開日や更新日ではありません。
2. main反映済みか、PR公開でmain未反映かを確認します。候補・追加設定用という種類は公開状況と別に読みます。
3. 公開版の検証範囲と確認日を読み、公開版を取得します。本文一致だけの確認は動作検証の合格ではありません。
4. サイズ・SHA256を開いて同じ版かを照合します。生成時の手元確認は一覧作成時のワークスペースの状態で、閲覧端末を検査した結果ではありません。
5. 前回からの変更で版・本文の差を確認します。比較対象は固定した前の公開ZIP 20261012.1です。一覧を再生成しても比較対象は勝手に動きません。

| 表示 | 意味 |
|---|---|
| main反映済み | 固定mainコミットの公開本文を確認済み |
| PR公開・main未反映 | PR側の固定コミットを公開。通常のmain版への反映はまだ |
| 公開版の本文一致 | 固定公開ファイルとSHA256が一致。製品動作を保証する意味ではない |
| 検証合格 | 表示した固定版の、記載した範囲の検証が合格 |
| 内容変更・要再確認 | 手元のファイルが公開・検証記録と違う |
| 未保存・公開先から取得 | 記録されたファイルが一覧生成時のワークスペースにない |
| 手元は未照合 | 独立公開用の一覧など、ローカルファイルを診断していない |

CSV・Markdown・JSONも同じ正本から生成します。CSVを表計算ソフトで開く場合はUTF-8を使います。差分の登録解除は一覧から外れた意味で、原本削除の操作ではありません。

## 更新方法とツール統合

正本は `catalog/artifacts.json`、生成処理は `tools/artifacts.py` です。既存の `tools/manage.py build` / `all` / `check` に接続しています。共通登録のcatalogueは成果物・全ファイル・ライブラリの一覧をまとめて更新し、正本JSONと生成コードも入力照合の対象にします。新しい重複実行コマンドを増やしません。

```sh
python tools/manage.py build
python tools/manage.py check
python tools/manage.py doctor
```

公開状態や検証結果は記録に基づきます。生成時にネットワークへアクセスして自動でmain反映や合格に昇格させません。新しい公開版を登録するときは、公開コミット・本文SHA256・サイズ・PR状態・検証根拠を確認してから正本を更新します。検証が別のSHA256を指す登録は拒否します。

公開ZIP 20261012.2は以前に公開・6環境検証済みです。今回追加した一覧生成コードは開発中のワークスペース側の更新で、既存ZIPへ入っているという意味ではありません。新ZIPに取り込む段階では、その新しい内容を別途配布・検証します。

## 次の統合・更新案

| 優先 | 更新案 | 完了条件 |
|---|---|---|
| 実施 | 正本から成果物4形式を生成し、既存build/checkへ接続 | 再生成が安定し、改変・古い一覧を検出。検索・状態絞り込み・モバイル・リンクを検証 |
| 実施 | 公開記録と成果物正本の共通確認・更新案出力 | 公開実バイト・コミット・検証根拠を確認し、旧記録を履歴として保持。通信失敗時は以前の合格を新規確認として扱わない |
| 次 | 変更した登録入力に対応する検証を案内 | 共通registryの入力照合を利用し、必要な再検証を表示。省略した検査を合格扱いにしない |
| 実施 | 共有ルールと原本・ミラーの関係を表示 | SHA256一致と用途を確認し、Git履歴・購読先を維持したまま関係を整理 |
| 本体取得後 | 録画・AI・Windows操作の成果物登録 | 正式ソース・依存・取得ハッシュ・起動と復旧の実機検証がそろった範囲を登録 |

## 公開記録の共通確認

```sh
python tools/manage.py run --tool artifact-publication
# 確認結果を基に別ファイルへ更新案を出す場合
python tools/check_artifact_publication.py --candidate work/artifacts-proposal.json
```

この確認はネットワークを使います。固定公開版のサイズ・SHA256、取得した固定mainコミットの本文、PRの終了・マージ先を観測します。結果は `catalog/results/artifact-publication.json` に保存します。公開本文の一致は製品動作や新たなCI合格の判定ではありません。

正本は自動変更しません。更新案は新規のwork/*.jsonへ出し、確認・採用は別操作です。PRがmain以外のブランチへマージされても、それだけでmain反映扱いにはしません。mainの本文が記録のSHA256と一致した場合にだけ公開状態の更新を提案します。通信失敗・不完全な確認・古い正本への確認結果の使い回しからは更新案を作りません。既存のCI確認日は公開本文を再取得した日付で上書きしません。

共有ルールは、対応する原本SHA256と、順序を保ったルール・制御行のSHA256を記録します。sとfaaffの追跡リストは9行を共有します。生成時に一致する手元の原本があれば関係も再照合します。メタデータや出典の違いを保持し、動作同一性の保証や原本の自動削除には使いません。

## 更新用ZIPの適用

公開済みの基準ZIP20261012.2と、管理コード更新ZIP20261012.1を組み合わせて新しい作業先を用意できます。更新ZIPは公開済み候補17ファイルを固定コミットから取得してまとめたものです。全内容ハッシュと基準版を照合し、既存の出力先には上書きしません。適用に失敗した場合は、この処理が作った出力先を整理します。

リポジトリのルートで実行します。新しい仮想環境でsetupとallを実行してから使います。

```sh
python workspace-management/apply_catalogue_update.py --base workspace-management/workspace-source-20261011.zip --update workspace-management/catalogue-update-20261012.1.zip --update-sha256 010c64b23b6c8a66adadf9c43c8711f293d7ea4c2fe3f336c951682b37ec0fde --output work/updated-tools
```

更新ZIP内の一覧は作成時点の12対象を保持します。現在の公開一覧は更新ZIP自身を追加した13対象です。更新ZIPは基準ZIPを含む単独の製品配布ではなく、管理コードを更新するためのファイルです。

## 変更後に再検証する範囲

| 変更したもの | 必要な確認 | 判断の限界 |
|---|---|---|
| 一覧の説明・公開先・SHA256 | `manage.py build` → `manage.py check`、公開確認ツール | 本文照合だけで動作合格へ変更しない |
| 一覧生成コード・画面 | `manage.py test`、build/check、`browser_smoke.py` | 画面検証は録画やフィルター実機の検証を含まない |
| フィルタールール | `manage.py filters --check` と該当エンジン検査 | 一覧の再生成だけではルール動作を検証できない |
| 依存・Python・共通管理コード | 新規仮想環境でsetup/all、Linux・Windowsの対象Python CI | 以前の環境の合格を新しい環境へ流用しない |
| 配布ZIP・更新ZIP | 全内容ハッシュ、クリーンな新規先への適用、適用先でsetup/all | ソース候補の検証と実配布ZIPの検証を分ける |

上表は手動の案内です。doctorは前回の合格記録と現在の登録入力を比較し、変更ファイル・登録定義の変更・登録ツールの再実行コマンドを案内します。未登録の間接依存や外部状態を含む検査の自動選択は未実装です。検査を実行していない場合は未確認のまま扱います。

## 診断案内の追加候補

2026-10-13のdoctor.py/test_doctor.pyは開発ソースの追加候補です。公開済み更新ZIP20261012.1には含まれません。登録入力の変更と再実行案内を表示し、外部状態やすべての間接依存に対応する検証選択は行いません。管理ワークスペースで `python tools/manage.py doctor` を実行します。
