# 既存ツール調査・解析・再利用の標準運用

目的: 既存の優れたツールを調査し、製品改善へ適用する。**コードを直接コピー・改変してよい**。コピーそのものを目的にせず、現行実装との比較、ライセンス、安全性、検証を条件として最適な採用方法を決める。

## 手順

1. **検索**: 公式リポジトリ/仕様/リリース/Issueを確認。競合ツールや同機能の複数案を比較。
2. **原典固定**: URL、取得日、コミットSHA、ライセンス、依存ライブラリ、既知の問題を確認。ブランチ名だけで出典固定とみなさない。
3. **隔離取得**: 原本、参考コード、ZIPをGit外の隔離領域に保管。ハッシュ・ファイル一覧・危険パス・ライセンス表記を検証。未知のコードを無検証で実行しない。
4. **解析**: 入口、通信、権限、UI、Worker、HLS/DASH、保存経路、互換性、故障時処理を確認。事実・推測・未検証を分ける。
5. **採用判断**: `REFERENCE_ONLY`、`DIRECT_COPY`、`MODIFIED_COPY`、`INDEPENDENT_IMPLEMENTATION`、`REJECTED`を比較し、理由を残す。既存の正常機能や重複を優先して評価。
6. **統合**: 隔離した製品作業コピー/branchで最小差分実装。第三者コードをコピーするなら著作権表示・LICENSE/NOTICE・変更通知・再配布/ソース提供義務を各ファイル/依存物について確認。
7. **検証**: 構文/静的検査、ビルド、合成データ、既存回帰、隔離ブラウザ、実機・実サイト、公開判定を別々に記録。実施していない工程は`NOT_RUN`。
8. **上流追跡**: 固定SHA間の関連差分だけを再解析。無検証での自動上書きはしないが、必要なコピーや追従更新は許可。

## 管理場所

- `ai/research/`: 薄いテキスト台帳・決定理由・出典・検証境界。バイナリや外部リポジトリ丸ごとはコミットしない。
- 隔離ワーク/成果物ZIP: 原本コピー・詳細レポート・調査用ツール。実物の正本はハッシュで識別。
- 製品のブランチ: 採用した実コード、テスト、NOTICE。出典参照だけで製品へ適用済みと判断しない。

## 記録の見方

`catalog.json` は**参考資料の索引**であり、製品リリース台帳ではない。TwitchNoSubのWorker/HLS診断を参考にする場合も、RPLAY本体が `faaff/main` に存在するとは見なさない。HLS/M3U8、TS/fMP4、DASH/MPD、コーデックは独立の次元で分類する。

### 利用できる検査ツール

オフラインの参照ZIP検査・差分比較には別添 `Reference_Research_Environment_20261030_v2.zip`（sha256 `08ffdd249133017a0b55d98d00a257e5396a74ac3b08ec649f633e1142ccc21f`）の `reference_intake.py` を利用可能。10件の単体テスト成功。アーカイブ検査成功は製品E2E成功を意味しない。必要に応じてGit・ripgrep・Python unittest・Node test・Playwright・web-ext・Semgrep・OSV-Scannerを選択。道具の導入そのものは目的にしない。

## 開発保護

`AGENTS.md` のゲート優先。 `main` に直接pushしない。merge/Release/公開範囲/ZIP追加/本番配布は所有者承認まで保留。署名付きURL・認証情報・Cookie・録画ファイル・機微ログを台帳に保存しない。
